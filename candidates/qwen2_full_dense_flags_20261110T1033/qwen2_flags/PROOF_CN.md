# 有限 BF16×BF16＋FP32 的两次舍入值与完整 flags 审计

## 值等价证明（不是硬件验证）
设 p 为精确 BF16 乘积，c 为原 FP32 累加器。两输入已经按原 RNE 量化为 BF16；有限 p 至多16个有效二进制位，c至多24位。BF16的最小非零数2^-133，故乘积最低2^-266；最大乘积低于2^256。乘积及下面所有FP64操作均不会发生FP64次正规、溢出或下溢，且乘积精确。

对非零p/c，令E为各自绝对值最高有效位指数，d为两E之差的绝对值。

1. d≤28：两项对齐后的整数表示从最高位到最低位至多28+24=52位。同号相加最多再进1位，共53位；异号抵消只减少最高位而不创造更低位。因此FP64和精确，之后一次FP32 RNE就是原FMA值。
2. d≥29：小项绝对值严格小于2^(E大-28)。若大项为有限可表示FP32值（c恒满足；正常范围的16位p亦满足），最近RNE边界距该大项至少2^(E大-25)，含2的幂处向下间距变化；次正规区边界距离为2^-150，亦更大。小项加上FP64舍入误差（至多约2^(E大-52)）无法触及该边界，所以精确和及FP64和舍入到FP32均仍为同一大项。
3. 若大项p≥2^128，其与FP32溢出边界2^128-2^103的距离也不可能被上述小项及FP64误差跨越（E=128时小项<2^100，更大E则距离更大），两者都溢出。若大项p在FP32次正规/更小区，非零c≥2^-149使d至多22，不可能属于d≥29分支。
4. 零项直接舍入另一个项；精确抵消与带符号零采用IEEE RNE加法规则。实现保持product及sum的符号零，不以abs重建输出。

因此对本审计的所有有限、已BF16量化乘数和有限FP32累加器，FP64精确乘法→FP64和→FP32与一次FP32 FMA的**值**等价。此结论不延伸到两个任意FP32乘数，也不包括NaN/Inf。

## flags 不能简单由FP64和比较获得
指数差大时FP64和可丢失小项，直接比较FP32结果与FP64和会漏报inexact。本实现使用无溢出/无下溢的Knuth TwoSum：

    s = p + c
    b = s - p
    e = (p - (s - b)) + (c - b)

其误差分解满足精确p+c = s+e。故inexact = (FP64(FP32(s)) != s) OR (e != 0)。当第一条件非零时，第二项不可能消除FP32结果与s的差（误差不超过半FP64 ulp）。tiny-after-rounding 且inexact产生UF；FP32溢出产生OF|NX。有限FMA不产生NV/DZ。flags采用原五位位序NV/DZ/OF/UF/NX，不改变fatal策略。

每一步仍按原K递增、同FP32累加器执行；无matmul、dot、einsum或归约重排。逐步等价归纳到完整矩阵的值/flags。保留所有结果为参考审计层，不代替原Chisel/HardFloat对照。

## 实际覆盖与限制
全七Dense阶段原M128真实输入、权重与已保存输出先逐文件SHA核验；每个实际FMA运行TwoSum误差及flags统计，所有输出逐字对照。RESULT只记录摘要，不提交生成数组/权重。
独立整数oracle测试及Fraction验证TwoSum精确残差，包含所有255×255有限BF16指数对、随机符号/尾数/累加器、符号零/溢出/次正规边界；测试不替代上述证明。
只覆盖七Dense，不包括QK/PV与全部标量/格式转换flags，不声称完整block异常契约或硬件PASS。五块硬件仍0/5，原head4 FAIL不变。

## 执行环境前提
证明要求IEEE RNE及gradual-underflow。fegetround只验证舍入模式，不单独证明FTZ/DAZ关闭；本环境另以次正规输入/结果边界和全指数对的逐例精确测试实测覆盖，未读取MXCSR逐位声明。若换平台，必须重新验证这些前提。数学分情况论证及有限测试不是机器形式验证证明。**输入FP32→BF16量化flags不在七Dense FMA flags范围内。**
