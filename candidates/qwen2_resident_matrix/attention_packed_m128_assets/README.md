# Separate packed M128 asset admission

This source-only adapter reuses the genuine original `be00eb8e4bc75e2e41f2a434d05d4c901ed3faa5`
M128 assets without changing historical files, receipts, logs or origins. It
neither grants numerical execution permission nor inherits a numerical verdict.
The original Public M128 run remains FAILED at its 2400-second inner work budget.
Native128's `PASS_BF16_STAGE_BUDGET` is strictly native evidence.

`provenance.json` pins the unchanged original ASSETS/setup/backend/payload,
sequential and reduced reference receipts, native16 prerequisite/native128
results, recipe libraries/dispatch metadata, and original failed Public receipt.
The new manifest uses profile `qwen2-public-pv16-packed-m128-linked-v1`, rows 128,
past zero, explicit raw/packed selection and the separate executing entry source
map. No M16 activation, arena, reference or result is relabeled as M128.

Admission hashes all 350 declared/ancillary original artifacts and all 285
original composed sources before and after. The authentic thirteen tensors,
M128 X (`ddcdcca67cb3e26007880a78074ea3eb70bf83e8d8060fa2258bb2c7644695df`),
M128 arena (`e96def26157427fc60a44f1af7a9a8443010eb5327c1ccb9b93c3b0e70fcafe7`),
zero-preload contract, native geometry, producer paths, exports, policy and
source/backend identity remain exact. Symlinks, path traversal, path/inode
aliases, duplicate/nonfinite JSON, boolean dimensions and source/byte drift fail.

The historical original ELF is retained as provenance only. The executing
combined packed ELF must be the qualified `a31f0cd5fd8184543ff489cc1cb2978d6f049c09eaa3edb24698e765360d4ff8`
with its original compile receipt `76ca454ca9433859b2cd517908759b26a5f311319efad9e780592c86a7d093ae`.
The unchanged current-tree `attention_packed_m16_entry.library_origin` verifier
checks original build paths, strict flags, compiler and execution C++ closure;
no ELF is loaded by admission. The successful repaired-M16 caller, summary and
source snapshot are separately required, with 27 assigned gates and full29
false. Its compatible arithmetic/owner/service/storage sources must match the
new execution tree. That prerequisite never supplies an M128 gate verdict.

API:
- `origin.source_snapshot()` is the source-only package/dependency closure
- `origin.snapshot(origin, content=False)` checks metadata and geometry only;
  `content=True` streams opaque bytes and still performs no numerical job
- `admission.seal_manifest(destination, *, origin, compile_receipt,
  compile_origin, m16_prerequisite)` creates a new private adapter receipt,
  outside every immutable origin, only after independent entry installation
- `admission.verify(path, digest, *, rows=128, enable_raw_kv=True)` returns the
  original `input_spec`, `reference`, `independent_reference`, `provenance`,
  `library_receipt` and `library` interface
- `read_manifest`, `verify_library`, `source_snapshot`, `own_sources`,
  `fresh_mode` and `snapshot_mode` retain the linked-entry signatures
- `read_reference_bytes` and `read_native_reference` preserve late hash checks
  and the original token-major Q/K decoder. Callers must retain the unchanged
  whole-terminal reference gate before invoking either comparison helper

Reference views expose one explicit root, `origin`; native and both original
oracle executions are truthfully marked reused. New forward, actual-chain,
old-pass inheritance and full29 acceptance claims remain false. Original
27-assigned-gate / 28-observed-stage semantics and diagnostic-only FP32 remain
owned by the unchanged numerical comparator.
