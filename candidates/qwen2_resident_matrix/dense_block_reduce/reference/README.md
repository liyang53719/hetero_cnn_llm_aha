# Independent QKV block/pair reference v1

`builder.transform(original_source_bytes, profile_bytes)` changes only the three explicit Q/K/V Dense calls in the hash-pinned official-BF16-v2 full-block C++ source. It adds a separate generic two-block, pair-high-first `dot16` helper and QKV wrapper. The original Dense function and every RMS, RoPE, QK, PV, softmax/exp7, FFN, bias and BF16 boundary remain byte-exact after reversing the three call substitutions and removing the marked helper. `verify_transform` enforces equality of the entire restored source, not selected substrings.

The block sizes come from the independently reviewed backend profile. Current evidence covers cold M16/M128, K1536, Q1536 and K/V256; [1024,512] is profile data, not a general model constant. The helper has explicit independent FP32 partial initialization, pair ordering, cross-block FP32 addition, then the original FP32 bias/BF16 write. Strict gradual underflow remains enabled. No actual owner, bank, Matrix implementation or actual intermediate output is imported into this reference producer.

`builder.regenerate_sources()` regenerates both the original candidate.cpp and block_layout.h from the existing hash-guarded repository generators. `profile.json` is an exact, tensor-free copy of the frozen six-shape backend metadata (SHA256 `07008af966dbe4d64b10f75c37e4d19e17159e3708543982a70c8ec996f1d5a5`). Source generation and the small tests require no historical work files.

`builder.prepare(rows, fresh_directory, archive_directory=..., snapshot_path=..., actual_summary_path=..., readonly_arena=...)` verifies the explicitly supplied archived run and original arena, binds the actual summary to its fixed snapshot before parsing that snapshot, checks the arena's raw x against the row-specific pinned actual input, and writes regenerated sources plus PREPARED.json. It does not compile or run. The optional arena must have exactly the original raw-input arena digest; intermediate preload substitution is not allowed. The archive, summary and snapshot arguments have no implicit historical-work defaults.

`run_reference` admits integer cold rows 16 or 128 with past=0. One explicit launch has a 10-second compilation limit and a 30-second M16 or 45-second M128 producer limit, one producer process/thread, and a 1 GiB address-space cap. Compilation may spawn compiler/linker children. The M128 budget uses the archived 30.5507-second reference as its estimate; no new M128 execution is implied by source support. The launcher freezes sources, profile, original input, compiler and commands, seals every output before reading archived official values, and retains original thresholds and historical FAILs. It does not execute a fresh official forward, actual chain, Java, Chisel or RTL.

`completed.reference_spec(directory, result_sha256)` verifies a completed producer and returns its comparison-only output inventory. The new producer is auxiliary to the unchanged official target. The old increasing-K producer must not become a second required acceptance gate for the changed QKV arithmetic. A successful producer comparison is not implementation acceptance. Completed-run verification still needs the original binary, arena, archive receipts and sealed outputs; the cold source test does not replace that execution evidence.

Eleven source/arithmetic tests cover exact C++/header regeneration, inverse-transform equality, rejection of unrelated edits and changed profiles, preserved execution provenance, explicit runtime archive paths, generic even-block validation, explicit M1/carried limits, C++ syntax, pair-order and independent-block cancellation controls, gradual underflow, and weight-stride/lane addressing. Seven workload tests additionally reject unsupported/noninteger/carried rows, crossed row receipts, missing/extra/mis-sized output files, previous-window raw inputs, and invalid summary/snapshot binding. They never run a full block or native forward. Run `python -m unittest candidates.qwen2_resident_matrix.dense_block_reduce.reference.test_builder candidates.qwen2_resident_matrix.dense_block_reduce.reference.test_workload -v` from a Git checkout with NumPy and g++ available; Torch is not required.

`python -m candidates.qwen2_resident_matrix.dense_block_reduce.reference.cold_check` copies only the required repository sources and this package to a temporary directory, starts a fresh Python process with no work directory, and rejects Python reads back into the original tree. It runs both test modules. The guarded generator reads the existing Git object database for its committed-HEAD source comparison; no Git mutation or historical work data is needed. Its source inventory includes the RMS generator's separately pinned test file. `COLD_CHECK.json` retains the earlier eleven-test packaging receipt and its original source inventory.

`workload.py` supplies shared shape admission, input pins and the exact 22-file output inventory. Completed evidence must agree across RESULT/PREPARED/FROZEN rows, actual input provenance and executed command, and contain all expected files with the right byte lengths. M16 outputs total 3,309,568 bytes; M128 total 29,229,056 bytes. Q/K archive decoding keeps the existing proven M16 token-major and M128 head-major distinction. The numerical generator, QKV profile, helper, acceptance thresholds and historical M16 receipt bytes are unchanged.

Cold packaging changed only Python wrappers, tests and metadata. Before those edits, `executed_m16_v1/` preserved all four executed source files and PREPARED/FROZEN/RESULT receipt bytes. Python snapshots use `.py.txt` so test discovery cannot import them. The completed adapter verifies these exact historical bytes when current wrappers differ, and reports that provenance explicitly. It never rewrites historical hashes. Regeneration still produces candidate SHA256 `e13bddc69714e6af6a774198d7382b4100f2f50cd843eea5d780bace14c6aacf` and header SHA256 `79d4b81277f3431d2e89e6807dc2deee425957a5549c7fffa71d8db8cba9af30`; M16 was not rerun for packaging.

The authorized M16 execution lives in `work/qwen2_official_public21_20261012/independent_qkv_reference_v1_m16_01`. Its 28 compared fields pass every applicable original numeric gate; FP32 softmax retains diagnostic-only status and no explicit mask is produced. QKV, Q/K, and complete scores are bit-exact.
