# Independent QKV block/pair reference v1

`builder.transform(original_source_bytes, profile_bytes)` changes only the three explicit Q/K/V Dense calls in the hash-pinned official-BF16-v2 full-block C++ source. It adds a separate generic two-block, pair-high-first `dot16` helper and QKV wrapper. The original Dense function and every RMS, RoPE, QK, PV, softmax/exp7, FFN, bias and BF16 boundary remain byte-exact after reversing the three call substitutions and removing the marked helper. `verify_transform` enforces equality of the entire restored source, not selected substrings.

The block sizes come from the independently reviewed backend profile. Current evidence covers cold M16/M128, K1536, Q1536 and K/V256; [1024,512] is profile data, not a general model constant. The helper has explicit independent FP32 partial initialization, pair ordering, cross-block FP32 addition, then the original FP32 bias/BF16 write. Strict gradual underflow remains enabled. No actual owner, bank, Matrix implementation or actual intermediate output is imported into this reference producer.

`builder.regenerate_sources()` regenerates both the original candidate.cpp and block_layout.h from the existing hash-guarded repository generators. `profile.json` is an exact, tensor-free copy of the frozen six-shape backend metadata (SHA256 `07008af966dbe4d64b10f75c37e4d19e17159e3708543982a70c8ec996f1d5a5`). Source generation and the small tests require no historical work files.

`builder.prepare(rows, fresh_directory, archive_directory=..., snapshot_path=..., readonly_arena=...)` verifies the explicitly supplied archived run and original arena, checks the arena's raw x against the supplied actual input snapshot, and writes regenerated sources plus PREPARED.json. It does not compile or run. The optional arena must have exactly the original raw-input arena digest; intermediate preload substitution is not allowed. The archive and snapshot arguments have no implicit historical-work defaults.

`run_reference` currently permits one explicitly launched cold M16 run, with separate 10-second compilation and 30-second single-process execution limits. It freezes sources, profile, input, compiler and commands, seals every output before reading archived official values, and retains original thresholds and historical FAILs. It does not execute a fresh official forward, actual chain, Java, Chisel or RTL. The source-only preparation API supports M128; M128 execution is intentionally not enabled in this launcher yet.

`completed.reference_spec(directory, result_sha256)` verifies a completed producer and returns its comparison-only output inventory. The new producer is auxiliary to the unchanged official target. The old increasing-K producer must not become a second required acceptance gate for the changed QKV arithmetic. A successful producer comparison is not implementation acceptance. Completed-run verification still needs the original binary, arena, archive receipts and sealed outputs; the cold source test does not replace that execution evidence.

Eleven small source/arithmetic tests cover exact C++/header regeneration, inverse-transform equality, rejection of unrelated edits and changed profiles, preserved execution provenance, explicit runtime archive paths, generic even-block validation, explicit M1/carried limits, C++ syntax, pair-order and independent-block cancellation controls, gradual underflow, and weight-stride/lane addressing. They never run a full block or native forward. Run `python -m unittest candidates.qwen2_resident_matrix.dense_block_reduce.reference.test_builder -v` from a Git checkout with NumPy and g++ available; Torch is not required.

`python -m candidates.qwen2_resident_matrix.dense_block_reduce.reference.cold_check` copies only the required repository sources and this package to a temporary directory, starts a fresh Python process with no work directory, and rejects Python reads back into the original tree. The guarded generator reads the existing Git object database for its committed-HEAD source comparison; no Git mutation or historical work data is needed. Its source inventory includes the RMS generator's separately pinned test file. `COLD_CHECK.json` records the verified cold run.

Cold packaging changed only Python wrappers, tests and metadata. Before those edits, `executed_m16_v1/` preserved all four executed source files and PREPARED/FROZEN/RESULT receipt bytes. Python snapshots use `.py.txt` so test discovery cannot import them. The completed adapter verifies these exact historical bytes when current wrappers differ, and reports that provenance explicitly. It never rewrites historical hashes. Regeneration still produces candidate SHA256 `e13bddc69714e6af6a774198d7382b4100f2f50cd843eea5d780bace14c6aacf` and header SHA256 `79d4b81277f3431d2e89e6807dc2deee425957a5549c7fffa71d8db8cba9af30`; M16 was not rerun for packaging.

The authorized M16 execution lives in `work/qwen2_official_public21_20261012/independent_qkv_reference_v1_m16_01`. Its 28 compared fields pass every applicable original numeric gate; FP32 softmax retains diagnostic-only status and no explicit mask is produced. QKV, Q/K, and complete scores are bit-exact. This prepares the new actual-chain comparison; it does not claim that chain has run or passed.
