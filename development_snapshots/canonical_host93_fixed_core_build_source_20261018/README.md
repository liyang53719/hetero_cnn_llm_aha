# Fixed core build gate: portable SOURCE template

This nine-file publication preserves every production function from the reviewed three-phase build gate. Only plan length/SHA and the loader's runner SHA change. No installer, generic supervisor, automatic binding mechanism, native binary, build artifact, actual review directory or system-tool hash inventory is included. INSTALL_MAP specifies the intended repository-relative placement; this candidate does not install or edit the repository.

## Two deliberately separate paths

Production loader: use Python -I -S -B and independently verify loader raw length/SHA before compiling the same buffer. Every actual stage/version/tiny and previous-phase binding is null. With --phase PHASE --execute-reviewed, the real loader reaches the unchanged validation and raises ValueError: stage actual PENDING before copy, mkdir or native spawn. Supplying a repository path is not a production option.

Without --execute-reviewed, unchanged main attempts SOURCE projection inspection. Its support paths are /UNBOUND placeholders, so inspection is unavailable until bound and currently raises FileNotFoundError, not a PENDING result. The cold suite exercises both exact real-loader branches with write/mkdir/spawn guards. Neither branch launches native work in this template. No production function was changed to hide that distinction.

Cold inspection: python3 -I -S -B test_build_gate_cold.py --repo /absolute/repository (add -O for optimized guards). Verify the cold script raw identity before same-buffer compilation when accepting it. --repo is required and only resolves the two exact published support sources in a deep-copied cold plan. Their full raw length/SHA is checked before AST projection. The production plan and actual identities remain unbound. No project module is imported by name. Relocation checks use source-text copies and mock/synthetic work only.

## Fixed contract retained

Phases are autoconf, configure and optimized_backend only. Totals180/180/3600s; pre10; work/CPU160/160/3570; latest170/170/3580; cleanup5; AS1/1/4GiB; FSIZE64MiB/64MiB/1GiB; tree acceptance64MiB/128MiB/2GiB; log acceptance256KiB/256KiB/1MiB; sampler200/200/3700 rows. One CPU and make-j1. CPU/AS are per process, FSIZE per file. Tree/log limits are soft acceptance bounds, not aggregate/live quotas.

The five canonical WNOWAIT supervision functions and four observation functions retain their pinned fragments and exact reversible projection. Samples are original-leader-only, usually make rather than its compiler descendants, with1-second no-catchup timing, PID/starttime anchor, <=2048-byte flushed rows. Separate Python processes record cumulative RUSAGE_CHILDREN after cleanup attempt; maxrss is not a difference or simultaneous subtree peak.

Source473 Git/size/SHA identities and fixed67 official package-member identities remain portable. The derived68th cfg is machine-path-dependent, not an official original: its bytes/SHA are null in GATE_PLAN. A new target must rederive the four resource-path lines, hash the cfg, and obtain a new accepted stage identity before any actual launch. Only SAFE_HISTORY records its old size/SHA, as non-reusable history.

Each actual phase requires independently reviewed exact local identities and a separately frozen plan/runner/loader pin successor. Autoconf uses a new473+68 copy tree; configure/make require an accepted exact preceding tree. INSTALL_MAP lists the unresolved bindings. The portable files do not grant actual execution permission or establish production/Host/backend correctness.

SAFE_HISTORY records accepted autoconf/configure generation and make RUNNING/PENDING_AT_FREEZE as reported at publication time. It cannot authorize reuse or substitute for a new workspace's actual evidence. Publication does not wait for, poll, or qualify the running build.
