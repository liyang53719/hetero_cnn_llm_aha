# 可重建权重与数值夹具的 Git 交付规则

## 当前工作树

- 不提交下载或转换得到的模型权重、QK 本地/远端 NPZ、原始运行报告或完整数值数组。
- 已从当前 Git 索引移除 RoPE 的 `local.npz`、`remote.npz`、`historical_arithmetic.npy`，合计 5,607,024 字节。原本地文件和缓存保留。
- `scripts/check_git_payloads.py` 检查索引内容，即使强制添加也会拒绝项目范围内的权重与可重建夹具。规则不禁止所有通用 NPZ 资产。
- 16 个 safetensors header 文件只包含长度前缀和 JSON 元数据，没有权重 tensor 字节；索引检查器会再次验证文件恰好止于 header。

## 两种来源不能混称

1. 既有 RoPE 历史回放：`scripts/materialize_rope_rounding_corpora.py` 从已经发布的固定历史提交下载，或从本地 Git 对象提取，然后核对原始大小和 SHA256。它恢复相同历史字节，不证明当前 CPU 能重新生成这些字节。
2. 新 QK 默认门禁：按官方 checkpoint、framework、源码及 CPU runtime 的固定版本下载有界权重，运行真实前缀和官方 producer，再确定性提取到 `work/`。每次生成新的来源记录。baseline/AVX2 两次执行的 5120 个 head 观察值不等于 5120 个互不相同的输入。
3. QK 历史回放只接受用户已有的原始缓存，作为可选本地回归；不会把新 CPU 结果标成旧历史夹具，也不在新源码中引用未发布的 Git blob。

## 复验与发布

根目录 `doc/` 保存计划、验收边界和 checklist。CI 先物化临时数据并验 hash，再运行普通/优化 Python 测试以及实际 RTL。当前修改的数值工作流只上传允许字段的简短摘要；完整数组、命令、主机环境详情和日志留在临时工作区。

这次是普通、可恢复的 main 后续提交，没有重写历史或强推。删除当前树的文件不会清除历史提交或已存在的 Git 对象，也不意味着仓库历史体积已经缩小。未来若需清除历史，必须单独评估并明确批准。
