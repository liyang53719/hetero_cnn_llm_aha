六组均通过，最大全绝对误差 0.015625；它与固定算术参考逐位一致是两个独立结论。
baseline 和 AVX2 的完整 native BF16 producer 审计均仍为 FAIL，不能由 V 局部门禁覆盖。

## 几何、命令与 BF16 生命周期

- 形状区分 hidden=1024、Q/context=2048、packed Q+gate=4096、KV=512、FFN=3584。
  原构造函数及旧 Qwen2 默认值保留；此新 Host profile 仅允许 V。
- 使用原 Command128 的 opcode 0x20、engine 2、flags 0，以及标准 typed tensor、
  MatrixOp、MatrixAux。显式 0x1a/0x1b 扩展采用 version 2 / role V；其他版本或角色拒绝。
- 三个 BF16 rank2 tensor 用 `(M,N,1,1)` 和元素 stride `(N,1,1)`。
  全部 21 条记录互异且准确终止；所有 owner-local 地址均为零 sentinel，由已有 owner 管理 SRAM。
- BF16 A 每 64B 含 32 个元素。上半拍保持并通过同一个 SRAM 写口落地，期间施加响应背压。
  不增加 SRAM 端口；旧 FP32 输入转换路径保持原语义。
- A/B/D 的实际字节数、地址增量、mask、writeBytes 与完成 ACK 均贯通 typed BF16。
  D 每拍打包 32 个 BF16-RNE 值，标量及 burst writeback 都覆盖。
- Host 检查完整 allocation 权限和无别名，再检查活动窗口来源可读性及目标新鲜性。
  仅在 owner 成功、确认字节数精确且 Host completion 接受后发布活动 D 区间。

官方 prefix 是 embedding → GDN 0/1/2 → layer3 的真实执行；A 来自归一化 producer07，
native V 来自 producer26，Wv 来自固定 checkpoint 原 BF16 权重。输入及来源按运行实际 SHA 保存。
固定源码与运行时版本不等于跨主机激活逐位一致；旧同 HEAD CI 已观察到上游 activation 字节差异，
权重/gamma/trig 相同，具体 kernel 与误差幅度尚未定位。各运行独立核验，不声称跨环境输入等价。

`a49bb313d5e1c3fbaf6661b7cf54ce4389196e319429acb43a2e193d8f9957d7`。
首次层级 Verilator 编译退出 255 / SIGKILL，随后对同一生成 RTL 与参数文件串行继续编译成功；
没有修改 DUT、生成 RTL 或期望值。旧完整运行收据原样保留，实际编译依赖另由编译输入清单提取。

运行数据、权重、NPZ、memh、生成 RTL、程序和完整 trace 均仅保留在 ignored work；Git 仅保存源码、

`.github/workflows/host-bf16-v.yml` 将该回归分成构建与运行两个 job：
构建 120 分钟，运行 350 分钟；模拟器本身最多 19500 秒，再留时间执行原验证器和上传摘要。
原 O3 程序实测速度估算连续运行约 4.3–4.9 小时，只是资源预算，不承诺 GitHub runner 必定按时完成。
GitHub hosted job 的上限为 6 小时（https://docs.github.com/en/actions/reference/limits）。

两个 job 仅传递必要程序、生成 RTL、合成命令夹具和身份清单，约 76 MB 未压缩。
压缩包 SHA 和源码 commit 通过 build job outputs 独立传递，先完整检查 allowlist、路径、长度与 SHA 再解包；
不传模型权重、NPZ、实际输出或参考输出。运行 job 从 reset 启动一次原程序，连续执行全部 42 条命令，
第 1 层直接读取实际第 0 层输出。原数值、ABI、拓扑及全量元素验证器全部通过后才可记录 PASS；
构建完成、超时、中断或缺失退出均不是数值通过。精确提交 CI 终态现已补齐如下。
