# hetero 项目维护约定

1. **项目全权维护与长期 push／发布授权。** 用户将 hetero 项目交由助手全权维护，并长期授权项目范围内的编码、测试、修复、可复核的小批提交、push main 和发布。普通 push 与既定项目范围内的发布不重复索要确认。工具等待、工具调用中断或会话中断不等于用户撤销授权，也不应成为停止独立可推进工作的理由。用户后续明确修改或撤回授权时，以最新指示为准；系统安全要求、必须单独批准的高风险操作及以下资源和数据边界仍然有效。

2. **授权范围只限 hetero 项目。** 本约定不扩展到其他项目、用户设备或无关账户，不引入 Voyager／Catapult 路线，也不以替代路线绕过本项目约束。

3. **验收必须真实，并精确标注 PASS／TEMP／FAIL／INCOMPLETE。** PASS 只覆盖实际执行、达到门槛且证据可复核的检查；实际失败记录 FAIL；已启动但未完整结束或证据链不完整记录 INCOMPLETE；尚未验证的临时结论保持 TEMP。不得继承不匹配的历史结果，不把文档检查、模型结果、合成测试、HLS 或微基准说成实际 RTL 或端到端验收通过。每项结论写明源码／配置身份、执行范围、产物及未覆盖部分。

4. **禁止上传权重及可重构权重的数据。** 不上传模型权重、local.npz、remote.npz，也不上传能够重构权重的文本、编码、分片或其他替代表达；用户输入、凭据及私有数据同样不得混入远端发布。允许提交项目源码、source pins、哈希和不包含权重的必要汇总证据。提交前检查文件清单与内容，防止运行依赖、缓存和大体积临时产物进入版本历史。

5. **按既定顺序完成五个 block 的真实 prefill128。** 顺序为 Qwen2-1.5B 典型 block、Qwen3.5-0.8B L0、Qwen3.5-0.8B L3、Qwen3.5-35B-A3B L0、Qwen3.5-35B-A3B L3。必须是实际 128-token prefill，不用 2×M1 或逐 token 循环替代，也不用较短序列、缩小几何或替代模型冒充完成。更长序列采用 1024 还是 1224 尚待确定，不阻塞 128 阶段；未完成项保留明确状态及下一步。

6. **先通过模型 prefill 数值对照，再冻结，最后做同刺激 RTL 验证。** 模型 prefill 数值实际通过后，冻结输入、参考结果、源码、配置、source pins 和相关哈希，再使用同一刺激执行对应 RTL 数值对照，使结果与冻结版本一一对应。源码、输入或配置变化后，不把旧证据自动套用到新版本。

7. **有效 MAC 目标与证据层级。** 修改模型和Chisel架构时同步考虑有效MAC至少80%、争取90%以上；固定资源和完整block周期分母，区分架构上界、周期预测、RTL实测以及理想供数、压力bench、目标内存条件，用实测校准。最终保留实际完整RTL数值与90%利用率目标，模型/契约/源码/HLS/子链不冒充RTL通过。

8. **先查状态，避免冲突与重复昂贵作业。** 开工前核对 main、中文计划及 todo／ongoing／done、既有任务与产物、源码／RTL 哈希和资源。未知长跑不重放、不擅自发进程信号；冻结工作树保持不动。可以在无冲突的独立检查点继续有界工作，局部未知状态不构成全局停工理由。

9. **如实按小时汇报。** 持续任务按小时说明已完成事项、当前证据、阻塞和下一步；重要结果、失败或需要用户决策的事项及时报告，不必等到整点。没有进展就如实说明，不用空泛保证代替实际工作，不虚构测试、提交、push、发布或 CI 状态。

10. **临时文件按任务要求盘点并可恢复地清理。** 每次检查临时文件清单；每日最多清理一次，仅处理已确认完成或不再需要、且已纳入 Git 跟踪的临时文件，使用普通删除提交保留 Git 可恢复性，不重写历史。保留源码、source pins、哈希、汇总和失败原因；不自动删除活动作业文件、仍被引用的文件、唯一证据或不可恢复的未跟踪文件。清理前后核对工作树与远端状态，并在按小时汇报中记录盘点、清理结果及保留原因。

11. **小步提交并闭环验证。** 保持中文计划清单同步，以小批、可复核提交推进，避免积压未提交改动。发布后核对远端准确提交与相关 CI；明确区分本地完成、远端已接收、CI 尚未结束和最终验收，不用中间状态冒充完成。
